# T-112 據點、QR 報到與自動派送

依據：`docs/system/11-meal-relay.md` v2.2。派送只透過 `meal_relay` 套件根的公開介面操作共用資料與規則。

## 端點

| 端點 | 權限 | 行為 |
|---|---|---|
| `GET /meal-relay/stations` | 全部角色 | 列出據點；回應不含 `checkin_code`。 |
| `GET /meal-relay/stations/mine` | 據點 | 回傳所屬據點、共用層產生的 QR 與到期時間，以及今天（臺北時間）的報到。 |
| `POST /meal-relay/checkins` | 志工 | 先驗證 QR，再建立報到與符合派送規則的任務；同日重複報到回傳既有報到與進行中任務。 |
| `GET /meal-relay/assignments/mine` | 志工 | 只回傳 `assigned` 任務；已完成或釋出的任務不再列出。 |

## 派送規則

- 報到呼叫共用層的 `verify_qr_text()`、`refresh()`、`elder_flags()`、`allergen_conflict()`、`food_status()`、`food_remaining()` 與 `to_*()`；共用規則不在本套件重寫。
- M16 候選限於所屬據點、警示中、未合併且沒有進行中任務的長者。依主要志工本人、沒有主要志工、主要志工今日未報到排序；同組先派較久未見者，再派離據點較近者；最多依 `DISPATCH_LIMIT` 派送。主要志工今日已報到時，該長者保留給他。
- M17 只對需要送餐的任務挑食物。食物須為 `open`、至少剩一份且沒有過敏衝突，依距據點距離與到期時間排序；找不到時仍建立關懷任務但不建立申請。自動建立的申請為 `claimed`，份數固定 1，並連結志工、長者與任務。
- 任務到期時間為派送時間加 `ASSIGNMENT_TTL_MIN`。每個請求由共用層 `refresh()` 處理過期任務及未取餐申請的釋出。
