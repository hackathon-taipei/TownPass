# T-120 管理系統 MR-P08（前端）

> 工單 #61｜合約 [11-meal-relay.md](../system/11-meal-relay.md) **v2.2** §2、§3 `meal_elder`、§6 M10、§7、§8｜ADR-024～ADR-026

管理員（代表社福單位與里長）在獨立網頁審核提供者、看看板與統計、維護長者名冊、重置 Demo。長者名冊只在這裡，志工手機上看不到（ADR-026、M13）。
網址：`/#/f/meal-relay/admin?as=<管理員帳號 id>`（§2：`?as=` 由 `data/client.ts` 存在裝置上）。不是 admin 一律顯示「沒有權限」與說明。

## 2. `logic/admin.ts`

| 介面 | 用途 |
|---|---|
| `useAdmin()` | 頁面狀態與動作（下表） |
| `accessOf(me)` | 只有 `admin` 回 `'admin'`，其他角色（含沒匯入的一般市民）回 `'denied'` |
| `errorMessage(e, fallback)` | `MealApiError` 的後端中文訊息（§7），其他錯誤用 fallback |
| `toLocalInput(iso)`、`fromLocalInput(value)`、`shortTimeText(iso)` | `datetime-local` 與 ISO（`+08:00`）互轉；「11/08 14:30」／「未設定」 |
| `emptyElderDraft()`、`draftOfElder(e)`、`validateElderDraft(d)`、`toElderCreate(d)`、`toElderUpdate(d, original)` | 長者表單：必填代號、位置、據點；代號像電話就擋下；建立只送合約欄位；修改只送改過的欄位、清空時間送 `null` |
| `seenText(days)`、`elderSummary(e, stations)`、`sortElders(elders)` | 名冊一列的文字；警示的在前、再依代號 |
| `pointStatusOf(point, foods)`、`boardMarkers(board)`、`elderMarkers(elders)`、`rosterMarkers(stations, elders, exceptId?)`、`sortFoods(foods)` | 看板與表單地圖的定位針、食物排序 |
| `sourcesOf(items)` | SourceNote 文字：據點與食物點的 `source` 以「、」拆開去重 |
| 常數 | `ADMIN_TABS`、`ORG_TYPE_LABEL`、`STAT_FIELDS`、`PRIVACY_NOTE`、`DENIED_TEXT`、`REVIEW_SETTLE_MS`、`BOARD_POLL_MS`（15 秒）、`ALIAS_MAX`（20） |
| 型別 | `AdminAccess`、`AdminTab`、`ReviewDecision`、`ElderDraft`、`ElderDraftErrors`、`ElderSummary`；轉出 `data/` 的 `Allergen`、`Board`、`BoardStats`、`Elder`、`Food`、`Location`、`Me`、`OrgType`、`Station`、`Supplier`（ui/ 不能匯入 data/） |

`useAdmin()` 回傳：

| 狀態 | 動作 |
|---|---|
| `access`（`loading`／`admin`／`denied`／`error`）、`accountId`、`me`、`accessError`、`tab`、`now`（每秒）、`version`（重置次數） | `start()`／`stop()`：每秒更新 `now`、看板分頁每 15 秒 `loadBoard()`，再 `init()` |
| `pending`、`reviewed`、`board`、`elders`、`roster`、`stations`、`foods`、`markers`、`formMarkers`、`sourceText` | `init()`：`getMe` → admin 才 `loadAll()`（`listSuppliers('pending')`、`getBoard`、`listElders`、`listStations`） |
| `errors.{review,board,elders}`、`staleAt`、`offline` | `review(id, decision)`：`reviewSupplier(id, 'approve'\|'reject')`，失敗提示並丟出錯誤 |
| `draft`、`editing`、`formErrors`、`saving` | `startEdit(elder)`、`resetForm()`、`saveElder()`（`createElder`／`updateElder`）、`reset()`（`resetDemo` 後重新載入、`version + 1`） |

## 3. 決策（合約沒寫清楚的地方）

| # | 決定 | 原因 |
|---|---|---|
| 1 | **偏離：不用 T01 PageContainer，新增 MR-C50 AdminShell** | T01 固定 `max-w-md`（手機寬）；管理系統是獨立網頁、電腦寬度為主，看板與名冊需要並排 |
| 2 | ReviewList 的 `approved`／`rejected` → `reviewSupplier` 的 `approve`／`reject` | 在 `logic/admin.ts` 的 `review()` 轉換，元件不知道端點 |
| 3 | 審核後先放進「剛審核的結果」，`REVIEW_SETTLE_MS`（晶片停留＋收合）後才從待審核移除 | 不打斷 MR-C19 的 D3 動畫 |
| 4 | 離線時審核改成唯讀清單、重置鈕隱藏，表單送出鈕停用 | MR-C19、MR-C22 沒有 `disabled`，不改共用元件；`review()`、`saveElder()`、`reset()` 在 `offline` 時也不送出 |
| 5 | 據點不預選 | 據點必填（ADR-026），要管理員明確選 |
| 6 | 代號看起來像電話（去掉空白與 `-` 後有 6 位以上連續數字）就擋下 | ADR-024：只填代號 |
| 7 | 修改長者只送改過的欄位；清空下次時間送 `null`；什麼都沒改就不送出 | 後端 `exclude_unset`，`null` 會清掉；避免空的 PATCH |
| 8 | 食物點顏色：還沒被派出 > 可派送 > 已全數派出 > 已過期／已下架 | 一個食物點有多批食物時取最需要注意的狀態（ui-kit.md 地圖顏色） |
| 9 | SourceNote 用據點與食物點的 `source`，以「、」拆開去重 | 開放資料來源跟著資料走，不寫死 |
| 10 | 看板每 15 秒重新取得（只在看板分頁） | 志工報到、送達會反映到統計與地圖；其他分頁不用輪詢 |
| 11 | 名冊清單做成一個元件 MR-C54 ElderRoster（交接時是一列一個 ElderRow） | 頁面模板超過約 80 行；本工單只有 MR-C50～C54 五個號碼 |
| 12 | 按「修改」時捲到表單 | 手機上表單在名冊下方 |

## 4. 測試（`services/web/tests/meal-relay-admin.test.ts`，mock `@/features/meal-relay/data`）

| 驗收項目 | 測試 |
|---|---|
| 非 admin 顯示沒有權限、不讀資料 | `accessOf 只有 admin 能進`、`%s → 沒有權限，不讀審核、看板、名冊`（citizen、volunteer、supplier、station）、`沒匯入的帳號（後端視為一般市民）→ 沒有權限`、`讀取時後端回 FORBIDDEN_ROLE → 改成沒有權限…` |
| admin 載入 | `admin → 讀取待審核（pending）、看板、名冊與據點`、`getMe 失敗 → error，顯示後端的中文訊息` |
| 建立長者送出的資料（station_id 必填） | `沒選據點 → formErrors.station_id，不呼叫 createElder`、`代號、位置也必填；代號像電話號碼就擋下`、`填好 → createElder 收到合約欄位（時間 +08:00）…`、`後端錯誤 → 回傳 false、名冊不變`、`toElderCreate 只送合約欄位` |
| 審核後清單更新 | `通過 → reviewSupplier(id, approve)、剛審核多一筆、等動畫結束才從待審核移除`、`不通過 → reviewSupplier(id, reject)`、`失敗 → 丟出錯誤（ReviewList 按鈕恢復），清單不變` |
| 修改長者、重置、離線 | `修改只送改過的欄位；清空下次時間送 null`、`toElderUpdate：沒改任何欄位回傳空物件…`、`修改時什麼都沒改 → 不呼叫 updateElder…`、`重置 → resetDemo 後重新載入、version + 1`、`離線（讀到 stale_at）→ offline，寫入都不送出`、`重新讀取成功後 stale_at 清掉，恢復可寫入` |
| 看板地圖、SourceNote、時間 | `pointStatusOf…`、`boardMarkers…`、`sourcesOf…`、`toLocalInput／fromLocalInput…` |

改壞測試：把 `accessOf` 改成 volunteer 也回 `'admin'`，`accessOf 只有 admin 能進` 與 `volunteer → 沒有權限…` 兩個測試失敗（`expected 'admin' to be 'denied'`），還原後全部通過。

### 6.4 決策

| # | 決定 | 原因 |
|---|---|---|
| 13 | 表單的「代號」是長者 id（唯讀，新增時顯示「儲存後自動產生」），「稱呼」是 `Elder.alias` | 工單合約；id 由後端產生。清單同時顯示稱呼與「代號 e-1」 |
| 14 | 「位置」（地圖選點）放在「更多設定」裡，新增長者時或位置有錯誤時自動展開 | 設計圖沒有畫位置欄，但合約 `ElderCreate.location` 必填 |
| 15 | 「不通過」先開確認視窗，但不填原因 | 合約 `reviewSupplier` 沒有原因欄位，既有行為也沒有；不新增 API |
| 16 | 不再使用 MR-C22、MR-C19，按鈕直接寫在管理系統元件裡 | 共用元件不能改（MR-C22 沒有確認、不是紅框；MR-C19 不是表格） |
| 17 | 新元件不用 MR-C100～C109 | `tools/check-arch.mjs` 只接受兩位數編號（`/^MR-[PC]\d{2}$/`）；工單不准改 check-arch，所以全部做在既有的 MR-C50～C54 |
| 18 | 看板加回總覽地圖（T-126 拿掉過） | 設計 v2 §3.6 與工單合約要求；長者定位針仍只在管理系統（M13） |
| 19 | 「已派送」= `dispatched_qty`（派出中：claimed＋delivering） | 設計圖的用語；提供者頁仍叫「派出中」 |
| 20 | 名冊離線時仍可點開看，只有「儲存變更」停用 | 看不是寫入；ADR-024 只要求寫入停用 |
