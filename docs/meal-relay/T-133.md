# T-133 據點、食物點、提供者地址（合約 v2.5）

> 工單 #94｜合約 [11-meal-relay.md](../system/11-meal-relay.md) **v2.5** §3、§4、§8、§10｜ADR-030

設計 v2 要在三個地方顯示地址：首頁的據點清單、志工任務卡的取餐地點、提供者申請與管理員審核。`Station`、`Point`、`Supplier` 原本只有座標，這張工單補上地址欄位。

## 改了什麼

| 位置 | 內容 |
|---|---|
| `models.py` | `meal_station.address`、`meal_point.address`、`meal_supplier.address`，`str`，預設 `""` |
| `schemas.py` | 回應：`Station.address`、`Point.address`、`Supplier.address`、`Food.point_address`；請求：`SupplierApply.address`、`PointCreate.address`（選填，最長 120 字） |
| `service.py` | `to_station`、`to_point`、`to_supplier`、`to_food`（`point_address` 由 `point_id` 查出） |
| `meal_account/service.py` | 申請時寫入地址，去掉前後空白；個人提供者（`person`）存 `""`（ADR-030） |
| `meal_food/service.py` | 建立食物點時寫入地址，去掉前後空白 |
| `seed/stations.json`、`points.json`、`suppliers.json` | 地址（見下） |
| `web/.../data/types.ts` | 上面的欄位，型別與後端一致（只新增欄位） |

id、`checkin_code`、`kind`、`created_by` 都沒改。

## 已部署的資料庫

`db.py` 啟動時會自動補上 `address` 欄位，舊資料的值是空字串。**啟動時的 `seed()` 只在還沒有任何帳號時才匯入種子**，所以已部署的資料庫不會因此出現種子地址；管理員要執行一次「重置示範資料」（`POST /demo/reset`）才會寫入。重置前，據點、食物點、提供者的地址都是空字串，畫面要能正常顯示（不顯示地址列）。

測試 `test_old_database_gets_empty_address_until_reset` 模擬這個情況：刪掉欄位、啟動同步、確認是空字串，重置後才有種子地址。
