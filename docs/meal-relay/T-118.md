# T-118 志工頁 MR-P04 與我的任務 MR-P05（前端）

> 工單 #59｜合約 [11-meal-relay.md](../system/11-meal-relay.md) **v2.2**（§2 志工、M8、M9、M11、M13、M15、M17、M18、§7、§9 掃描與斷網、§11 V7、V11、V15、V18、V20）

志工到據點掃 QR 報到，系統自動派給他要送餐或關懷的長者。志工**只看得到自己進行中的任務**，取餐、送達或關懷後回報，任務就從手機上消失，裝置上存的任務也一起清掉。

## 4. 合約沒寫清楚、這裡的做法

| # | 問題 | 做法 |
|---|---|---|
| 1 | 回報的 `kind` 怎麼決定 | 任務的 `claim_id` 在 `listMyClaims`（`claimed`、`delivering`）裡找得到 → `meal`，並帶 `claim_id`；找不到（沒有合適的餐，或已取消）→ `care`，不帶 `claim_id`。這樣取消後只做關懷不會把已取消的申請標成完成（M8、M9） |
| 2 | 還沒取餐能不能回報 | 不能：送餐要先「取餐」（`claimed → delivering`）才能回報；不送了就按「取消這份餐」，任務改成只做關懷（M8）。卡片上有說明文字 |
| 3 | 放門口的照片用 MR-C06 還是 MR-C17 的拍照鈕 | MR-C17 VisitResultPicker 選「放門口」時已經會展開自己的拍照鈕；再放 MR-C06 會出現兩個拍照鈕。所以用 MR-C17 的拍照鈕，壓縮照 MR-C06 的做法在 logic 做（`shared.ts` 的 `fitSize`、`IMAGE_QUALITY_STEPS`、`base64Bytes`），上傳 `uploadImage` 時送**完整的 data URL**（後端 `POST /images` 要 `data:…;base64,…`） |
| 4 | 過敏要用 MR-C20 嗎 | MR-C20 AllergenChips 是 11 個可點選的勾選鈕，拿來「顯示」會讓志工以為可以改。任務卡用文字列出長者的過敏原，有衝突時用 MR-C16 AllergenWarning 並停用取餐 |
| 5 | 任務完成後怎麼清裝置上的快取（§9） | 回報成功（或後端回 `NOT_OWNER`）後，把 `meal-relay.cache.<帳號>:/assignments/mine`、`/claims/mine` 裡這個任務與申請刪掉，再重新取得一次。資料層沒有清快取的函數，鍵的格式照 `data/client.ts`；之後若資料層提供 `dropCached()` 就改用它 |
| 6 | 重新打開志工頁時「報到的據點」從哪來 | 剛報到 → `CheckInResult.station`；重新打開 → 進行中任務的 `station_id` 對 `listStations()`。沒有任務時不顯示今天的狀態（合約沒有「我今天的報到」端點） |
| 7 | `NOT_OWNER`（V20） | 顯示後端訊息，把任務從畫面與快取移除（任務已完成或已釋出）並重新取得 |
| 8 | `FRESH_CANNOT_LEAVE`（V11） | 生鮮時 MR-C17 本來就不顯示「放門口」，送出條件也擋；後端仍回這個錯誤時顯示後端訊息並清掉選擇 |
| 9 | 掃描逾時 | `qr_code_scan` 等 5 分鐘；逾時或 App 回錯誤顯示「沒有掃到 QR code，請再試一次」 |
| 10 | 不是志工的帳號開志工頁 | 顯示「這一頁給志工使用」，不呼叫志工端點 |

### 6.4 設計圖與合約沒寫清楚、這裡的做法

| # | 問題 | 做法 |
|---|---|---|
| 1 | 「已完成 N 件任務」的 N | **這次開啟任務頁後回報成功的件數**（`reportedCount`）。合約沒有「我今天的回報」端點，也不新增 API；`NOT_OWNER` 移除的任務不算。一開始就沒有任務時顯示「目前沒有進行中的任務」，不是完成畫面 |
| 2 | 完成畫面什麼時候出現 | 這次頁面裡至少回報過一件，而且回報後重新取得的清單已經沒有進行中的任務 |
| 3 | 回到志工首頁後「已報到」從哪來 | 報到結果（據點、時間）記在記憶體（不存裝置、不含長者資料），同一位志工、同一天（臺北時間）有效；所以全部完成後回到志工首頁仍是「已報到」、「0 件待完成」、三步都打勾。重新整理 App 後記憶體清空，就跟 T-118 #6 一樣由進行中的任務推得 |
| 4 | 重新開啟頁面時的報到時間 | 進行中任務最早的 `assigned_at`（後端在報到當下派送，`assigned_at` 等於 `checked_in_at`，M16）；沒有任務就不顯示時間 |
| 5 | 狀態晶片的顏色 | 設計圖「待取餐」「配送中」是黃色，但 T-126 規定狀態只用三色、**不用黃色表示狀態**。保留 T-126：要做的事是 `primary-50` 淺底、狀態是白底 `primary` 細框。黃色只用在強調（「N 件待完成」、「還有 N 件」、「已完成 N 件」的數字、取餐地點底色） |
| 6 | 「查看位置」只有這位長者一根定位針 | 長者定位針只有這一位（M13）；T-126 已合併的任務據點與「我的位置」企鵝保留（不是長者）。收合時不建立地圖 |
| 7 | 我的任務頁首用一般標題還是 banner | 清單照 01 右與 README §3.3：大標「我的任務」＋「還有 N 件需要你」；完成畫面照 04 右用 BrandHeader banner |
| 8 | 回報面板右上「關閉」 | MR-C09 BottomSheet 是 kit 元件、沒有關閉鍵，不能改；在面板內容第一列放「關閉」並上移到標題那一列。點遮罩、按 Esc 仍可關閉 |
| 9 | 生鮮不能放門口 | 設計 v2 要「停用並說明」，kit 的 MR-C17 VisitResultPicker 是直接隱藏；改用新的 MR-C80（停用、寫原因：「生鮮蔬果不能放門口」或「這次只做關懷，沒有餐可以放門口」）。後端仍回 `FRESH_CANNOT_LEAVE` 時照舊顯示後端訊息並清掉選擇 |
