# T-118 志工頁 MR-P04 與我的任務 MR-P05（前端）

> 工單 #59｜合約 [11-meal-relay.md](../system/11-meal-relay.md) **v2.2**（§2 志工、M8、M9、M11、M13、M15、M17、M18、§7、§9 掃描與斷網、§11 V7、V11、V15、V18、V20）

志工到據點掃 QR 報到，系統自動派給他要送餐或關懷的長者。志工**只看得到自己進行中的任務**，取餐、送達或關懷後回報，任務就從手機上消失，裝置上存的任務也一起清掉。

## 1. 畫面（元件樹）

```
MR-P04 VolunteerPage = T01 PageContainer {
  MR-C05 StaleBanner、MR-C23 VolunteerAvatar＋名字、
  MR-C43 CheckinPanel { A01「掃描報到」（App：qr_code_scan）｜A04 貼上 QR 文字＋A01「報到」（瀏覽器） }、
  MR-C44 TodayStatus { M06 InfoTable（報到據點、報到時間）、任務數徽章（D6 .bump）、A01「前往我的任務」 }、
  A07 SourceNote（據點的 source）、MR-C12 ToastHost
}
MR-P05 TaskPage = T01 PageContainer {
  MR-C05 StaleBanner、
  MR-C40 TaskCard × 任務（TransitionGroup list）{
    長者代號、倒數到任務的 expires_at、MR-C04 ElderStatusTag、要做的事 A02（送餐／關懷）、
    MR-C07 MapView（只有這位長者一根定位針，不做導航）、過敏（文字）、
    MR-C41 TaskMeal { MR-C15 ClaimRow、MR-C16 AllergenWarning、A01 取餐、A01 取消這份餐 }、A01 回報拜訪
  }、
  M05 EmptyState（沒有任務 → 回志工頁報到）、A07 SourceNote、
  MR-C42 VisitReportSheet { MR-C09 BottomSheet、MR-C17 VisitResultPicker、MR-C10 SubmitButton }、MR-C12 ToastHost
}
```

**M13：** 志工頁只有任務「數量」，沒有長者清單或地圖；任務頁的地圖只放該任務那一位長者。整個志工端沒有呼叫任何列出長者的端點。

## 4. 合約沒寫清楚、這裡的做法

| # | 問題 | 做法 |
|---|---|---|
| 1 | 回報的 `kind` 怎麼決定 | 任務的 `claim_id` 在 `listMyClaims`（`claimed`、`delivering`）裡找得到 → `meal`，並帶 `claim_id`；找不到（沒有合適的餐，或已取消）→ `care`，不帶 `claim_id`。這樣取消後只做關懷不會把已取消的申請標成完成（M8、M9） |
| 2 | 還沒取餐能不能回報 | 不能：送餐要先「取餐」（`claimed → delivering`）才能回報；不送了就按「取消這份餐」，任務改成只做關懷（M8）。卡片上有說明文字 |
| 3 | 放門口的照片用 MR-C06 還是 MR-C17 的拍照鈕 | MR-C17 VisitResultPicker 選「放門口」時已經會展開自己的拍照鈕；再放 MR-C06 會出現兩個拍照鈕。所以用 MR-C17 的拍照鈕，壓縮照 MR-C06 的做法在 logic 做（`shared.ts` 的 `fitSize`、`IMAGE_QUALITY_STEPS`、`base64Bytes`），上傳 `uploadImage` 時送**完整的 data URL**（後端 `POST /images` 要 `data:…;base64,…`） |
| 4 | 過敏要用 MR-C20 嗎 | MR-C20 AllergenChips 是 11 個可點選的勾選鈕，拿來「顯示」會讓志工以為可以改。任務卡用文字列出長者的過敏原，有衝突時用 MR-C16 AllergenWarning 並停用取餐 |
| 5 | 任務完成後怎麼清裝置上的快取（§9） | 回報成功（或後端回 `NOT_OWNER`）後，把 `meal-relay.cache.<帳號>:/assignments/mine`、`/claims/mine` 裡這個任務與申請刪掉，再重新取得一次。資料層沒有清快取的函數，鍵的格式照 `data/client.ts`；之後若資料層提供 `dropCached()` 就改用它 |
| 6 | 重新打開志工頁時「報到的據點」從哪來 | 剛報到 → `CheckInResult.station`；重新打開 → 進行中任務的 `station_id` 對 `listStations()`。沒有任務時不顯示今天的狀態（合約沒有「我今天的報到」端點） |
| 7 | `NOT_OWNER`（V20） | 顯示後端訊息，把任務從畫面與快取移除（任務已完成或已釋出）並重新取得 |
| 8 | `FRESH_CANNOT_LEAVE`（V11） | 生鮮時 MR-C17 本來就不顯示「放門口」，送出條件也擋；後端仍回這個錯誤時顯示後端訊息並清掉選擇 |
| 9 | 掃描逾時 | `qr_code_scan` 等 5 分鐘；逾時或 App 回錯誤顯示「沒有掃到 QR code，請再試一次」 |
| 10 | 不是志工的帳號開志工頁 | 顯示「這一頁給志工使用」，不呼叫志工端點 |

## 5. 測試對照（`services/web/tests/meal-relay-volunteer.test.ts`）

| 驗收 | 測試 |
|---|---|
| 掃描取消不送出 | `掃描取消（App 回傳 null）就不送出報到`、`normalizeScan：取消（null）、空白、不是字串都不送` |
| 掃 QR 報到並看到任務 | `掃到 QR 就用掃到的文字報到，顯示據點與任務數`、`瀏覽器沒有 App：改成貼上 QR 文字，不呼叫掃描` |
| V18 `QR_EXPIRED` 訊息 | `V18 QR_EXPIRED：請掃據點畫面上最新的 QR` |
| `WRONG_STATION`、`NOT_FOUND` | `WRONG_STATION、NOT_FOUND 顯示後端訊息（§7）` |
| V15 | `V15 同一志工重複報到拿到同一批任務：提示沒有重複派送` |
| M13 沒有長者清單或地圖 | `M13 志工頁沒有長者清單或地圖：只回傳任務數，不呼叫任何列出長者的端點` |
| V7 | `V7 取消這份餐：任務保留，改成只做關懷`、`taskViews：只有 assigned；申請已取消 → 只做關懷` |
| 取餐 | `取餐：claimed → delivering`、`送餐要先取餐才能回報（reportReady）` |
| 放門口沒照片不能送出 | `放門口沒有照片不能送出` |
| V11 生鮮不能選放門口 | `V11 生鮮不能選放門口：canLeaveAtDoor、送出鍵停用，後端 FRESH_CANNOT_LEAVE 時清掉選擇` |
| V20 回報後任務消失、快取清掉 | `V20 回報後任務從清單移除，裝置上的快取也清掉` |
| V20 `NOT_OWNER` | `V20 回報不屬於自己任務的長者（NOT_OWNER）：顯示後端訊息並移除任務` |
| ADR-024 斷網 | `斷網（stale_at）時停用報到`、`斷網時不送取餐，回報也停用` |
| 回報內容 | `buildVisit：送餐帶 claim_id；放門口帶照片；只做關懷不帶申請` |
