# T-113 管理員看板（後端 `meal_board`）

> 工單 #49｜合約 `docs/system/11-meal-relay.md` v2.2 §8 `getBoard`、§6 M1、M10｜ADR-024～ADR-026

管理員在管理系統（MR-P08，T-120）一頁看到據點、食物點、食物、長者、申請與今天的統計，用於 Demo 與評審說明成效。

## 端點

| 動作 | 方法與路徑 | 角色 | 回應 |
|---|---|---|---|
| `getBoard` | `GET /meal-relay/board`（帶 `X-Demo-User`） | admin | `Board` |

- 沒帶 `X-Demo-User` → 401 `UNAUTHENTICATED`；非 admin（含沒匯入的一般市民）→ 403 `FORBIDDEN_ROLE`（§7）。
- 先跑 `refresh`（M20，由 `CurrentAccount` 處理），所以過期取消（M6）、任務完成與釋出（M18）會先寫回再組裝。

## 程式位置

| 檔案 | 層 | 內容 |
|---|---|---|
| `services/backend/src/townpass_backend/features/meal_board/__init__.py` | 介面 | 匯出 `router`、`get_board` |
| `.../meal_board/api.py` | HTTP | `meal_router("meal_board")`、`require_roles("admin")`，只呼叫 service |

沒有自己的資料表與種子。共用的東西只從 `townpass_backend.features.meal_relay`（套件根）取用：`repo`、`schemas`、`to_station`／`to_point`／`to_food`／`to_elder`／`to_claim`、`local_day_start`、`now`。不重寫 M1（剩餘、派出中、已送達、食物狀態）與 M10（長者警示），一律用 `to_food`、`to_elder` 算好的欄位。套件放在 `features/` 底下會自動載入，不用改 `main.py`。

## 回應內容

`Board{stations, points, foods, elders, claims, stats}`（型別在 `meal_relay/schemas.py`，前端 `data/types.ts` 已對齊）：

| 欄位 | 內容 |
|---|---|
| `stations` | 全部據點（`Station` 不含 `checkin_code`，M15） |
| `points` | 全部食物點；`open_food_count` = 這個點 `status = open` 的食物數 |
| `foods` | 全部食物（含已下架、已過期，管理員要看得到），計算欄位依 M1、M5 |
| `elders` | 長者名冊，**不含 `merged_into` 有值的**（M13）；警示依 M10 |
| `claims` | 申請，**不含 `cancelled`** |
| `stats` | 見下表 |

## 統計規則（`stats`）

「今天」= 台北時間（+08:00）今天 0 點起到現在（`local_day_start(now)`）。

| 欄位 | 算法 |
|---|---|
| `foods_open` | `status = open` 的食物數（M1：沒下架、沒過期、還有剩） |
| `delivered_today` | `status = done` 且 `done_at` 在今天的申請，`qty` 合計（即 M1 的「已送達」份數；M3 每筆固定 1 份，所以也等於筆數） |
| `seen_today` | 今天有 `result = seen` 拜訪回報的長者**人數**（同一位見到兩次算 1 位；`left_at_door`、`returned` 不算；已合併的長者不算） |
| `alerts` | 看板長者中 `alert = true` 的人數（M10：`care_due` 或 `meal_due`） |
| `checkins_today` | 今天報到的志工**人數**（同一位志工重複報到算 1 位） |

### 合約沒寫清楚、這裡的決定

- `delivered_today` 用份數合計而不是筆數：與 `Food.delivered_qty`（M1）同一個意思；目前 M3 每筆 1 份，兩者相同。
- `seen_today`、`checkins_today` 算「人數」而不是「筆數」：看板是說明成效（今天見到幾位長者、幾位志工出勤），重複回報或重複報到（M17 回傳既有任務）不該灌水。
- `seen_today` 看拜訪紀錄（`meal_visit`），不看長者的 `last_seen_at`：種子的 `last_seen_at` 是相對時間（例：`now-3h`），會因為跑 Demo 的時刻跨日而忽算忽不算；拜訪紀錄才是今天真的有回報。
- `foods` 不過濾已下架／已過期：合約沒有要求過濾，管理員要看得到全部庫存去向。

## 測試對照（`services/backend/tests/test_meal_board.py`）

| 測試 | 驗證 |
|---|---|
| `test_board_seed_stats` | 種子資料：`foods_open = 6`、`alerts = 7`、其餘 0；與 `to_food`／`to_elder` 一致；清單筆數；`open_food_count` |
| `test_board_stats_count_today_done_and_seen` | 加一筆今天 `done` 的申請與今天 `seen` 的拜訪 → `delivered_today = 1`、`seen_today = 1`；昨天的、`delivering`、`left_at_door`、`returned`、同一位長者重複見到都不多算 |
| `test_board_stats_follow_elder_alert` | 長者 `last_seen_at`、`last_meal_at` 更新後 `alerts` 少 1（M10） |
| `test_board_stats_foods_open_follows_m1` | 全數派出（`claimed`）與下架（`closed`）的食物不算 `foods_open` |
| `test_board_stats_checkins_today_counts_volunteers` | 今天報到的志工人數；重複報到與昨天的不算 |
| `test_today_is_taipei_time` | 「今天」的起點是 +08:00 的 0 點 |
| `test_board_claims_exclude_cancelled` | `claims` 不含 `cancelled` |
| `test_board_elders_exclude_merged` | `elders` 與 `alerts` 不含 `merged_into` 有值的長者 |
| `test_get_board_as_admin_matches_board_type` | `GET /meal-relay/board`（admin）200，回應通過 `Board` 驗證，欄位齊全、時間含 `+08:00`、`Station` 沒有 `checkin_code` |
| `test_get_board_non_admin_is_forbidden` | volunteer、supplier、station、citizen、沒匯入的 id → 403 `FORBIDDEN_ROLE` |
| `test_get_board_without_header_is_unauthenticated` | 沒帶 header → 401 `UNAUTHENTICATED`（V1） |

統計的測試直接呼叫 `meal_board.get_board(session, at=T0)` 固定時間，昨天的資料放在台北時間 0 點前 1 分鐘，不會因為跑測試的時刻跨日而失敗。
