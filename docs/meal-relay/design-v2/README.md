## 1. 品牌與共用外觀（T-132 負責）

- **名稱**：主名「鄰食蜂」，副名「鄰食轉運站」。標誌在 `services/web/public/meal-relay/brand/`（T-132 放）。
- **顏色**：沿用 `services/web/src/style.css` 的 token，不要寫死色碼。
  - 主色（按鈕、選中的分頁）：`primary-600`／`primary-700`。淺底用 `primary-50`／`primary-100`。
  - 強調（數字、提醒卡）：`secondary-400`～`secondary-500`（蜂蜜黃）。淺黃提醒卡用 `secondary-50`／`secondary-100`。
  - 警示（過敏原、重置、刪除）：紅色系 token。
  - 標誌文字的深綠只出現在標誌圖片裡，不另外做 token。
- **字**：標題粗體大字。粉圓體由 #69（T-124）處理，有就用，沒有不等。
- **按鈕**：主按鈕是滿版圓角深青色，次按鈕是白底青框。一個畫面只有一個主按鈕。按鈕高度至少 48px（使用者多是年長志工）。
- **共用元件**（T-132 新增，編號 `MR-C60`～`C69`）：

| 元件 | 用在 | 設計圖 |
|---|---|---|
| `BrandHeader` 頁首：企鵝頭像＋「鄰食蜂」字標＋小字「鄰食轉運站」＋直線分隔＋頁面標題；變體 `banner`：淺青底、企鵝在左、標題置中、右邊房子與光芒裝飾 | 提供者、管理系統（字標版）；據點、我的任務、完成（banner 版） | 03、02、04 |
| `BrandHero` 首頁主視覺：完整標誌＋兩行標語 | 首頁 | 01 左 |
| `MascotBadge` 企鵝圓形頭像（可帶光芒） | 志工首頁問候、完成畫面 | 01 中、04 右 |
| `StepIndicator` 步驟列：圖示＋文字＋箭頭，標示目前步驟 | 志工首頁（報到→取餐→回報）、上架（拍照→填寫資訊→上架） | 01 中、03 右 |
| `InfoNote` 淺黃提醒卡（圖示＋文字，可帶第二行小字） | 首頁「長者不用操作 App」、申請「審核通過後…」、上架「上架後仍可修改…」、庫存「還有食物等待派送」 | 01、03 |
| `Accordion` 收合列（標題、右側晶片、箭頭；一次只展開一個的群組模式） | 首頁「想成為志工？」、任務卡、「查看位置」、「已結束的食物（N）」 | 01、03 |

| `NumberStepper` −／數字／+ | 上架份數、修改份數 | 03 右 |

## 2. 點擊流程（全部）

路由**不新增**，仍是 `index.ts` 的 6 個。同一頁裡的切換用網址 query，讓 App 返回鍵能退回上一個狀態：`supplier?tab=inventory|publish`、`admin?tab=review|board|elders`。

```
首頁 ─┬─ 一般市民「我要提供食物」 ─────────→ 提供者頁（申請）
      ├─ 提供者「管理我的食物」 ───────────→ 提供者頁（我的庫存）
      ├─ 志工「進入志工頁」 ───────────────→ 志工首頁
      ├─ 據點「打開報到 QR」 ──────────────→ 據點頁
      ├─ 附近關懷據點的一列 ───────────────→ 底部面板：地址＋地圖（只有這個據點）
      └─「想成為志工？」───────────────────→ 原地展開說明與 3 個連結
志工首頁 ─┬─（未報到）「掃描據點 QR 報到」─→ App 掃描 → 成功後畫面變成已報到
          ├─「查看我的任務」 ──────────────→ 我的任務
          └─「重新掃碼報到」 ──────────────→ App 掃描（重複報到不會重複派送）
我的任務 ─┬─ 任務卡（收合列，一次展開一張）
          ├─「確認已取餐」 ────────────────→ 卡片變「配送中」，主按鈕換成「回報拜訪」
          ├─「回報拜訪」／純關懷的主按鈕 ──→ 底部面板：回報
          ├─「取消這份餐」 ────────────────→ 確認視窗 → 卡片變「純關懷」
          ├─「複製地址」、「查看位置」（展開地圖）
          └─ 最後一張回報完 ───────────────→ 完成畫面「回到志工首頁」→ 志工首頁
回報面板 ── 三選一 →（放門口）拍照 →「送出回報」→ 面板關閉、卡片消失、提示「已回報」
提供者頁 ─┬─ 未申請：申請表 →「送出申請」→ 審核中畫面
          ├─「已申請？查看審核狀態」 ──────→ 重新讀取申請狀態
          ├─ 通過：「我的庫存｜上架食物」分段切換
          ├─「＋ 上架新食物」 ────────────→ 上架食物分頁
          ├─「修改」 ─────────────────────→ 底部面板：份數、最晚食用時間
          ├─「下架」 ─────────────────────→ 確認視窗
          └─「確認上架」 ─────────────────→ 回到我的庫存，新的一列高亮，提示「已上架」
據點頁 ── 單頁，QR 自動更新（沒有可點的流程）
管理系統 ─┬─ 分頁：待審核（數字徽章）｜服務看板｜長者名冊
          ├─「重置示範資料」 ──────────────→ 確認視窗 → 重置後內容淡入
          ├─ 待審核「通過」／「不通過」（不通過先確認）
          └─ 長者名冊：點一位 → 右側表單（手機：底部面板）→「儲存變更」；「新增長者」→ 空白表單
```

角色不對時：頁面顯示一行說明（例如「這一頁給志工使用」）和「回首頁」按鈕，不呼叫該角色的 API。

## 3. 各畫面元素

### 3.1 首頁 MR-P01（01 左，T-134）
由上而下：
1. `BrandHero`
2. 依角色的主按鈕：方塊圖示＋文字＋右箭頭。文字見 §2。admin 沒有按鈕。
3. `InfoNote`：「長者不用操作 App」／「需要送餐或關懷，請洽里長或社區關懷據點」（主視覺標語：「長者不必用手機，也能收到餐食與關懷」）
4. 「附近關懷據點」：每一列是定位圖示、據點名稱、地址（`Station.address`，T-133）、右箭頭
5. `Accordion`「想成為志工？」
6. 頁尾小字：「據點資料：臺北市政府社會局」（SourceNote）

### 3.2 志工首頁 MR-P04（01 中，T-135）
- 標題「今天的服務」
- 問候：`MascotBadge`＋「{名字}，辛苦了！」＋「已報到」晶片（未報到時是「還沒報到」）
- 報到卡：房子圖示、據點名稱、「今天 HH:MM 報到」、分隔線、大數字「N 件待完成」、主按鈕「查看我的任務 →」
- 次按鈕「重新掃碼報到」，下方小字「重複報到不會重複派送」
- `StepIndicator` 報到 → 取餐 → 回報：
  - 有待取餐的任務時，目前步驟是「取餐」
  - 都在配送中時，目前步驟是「回報」
- 未報到：問候＋說明＋主按鈕「掃描據點 QR 報到」＋ StepIndicator（目前步驟是「報到」）

### 3.3 我的任務 MR-P05（01 右、04 中右，T-135）
- 標題「我的任務」，副標「還有 **N** 件需要你」（N 用黃色大字）
- 任務卡（`Accordion` 群組）：
  - 標題列：長者代號、晶片「送餐+關懷」／「純關懷」、狀態晶片「待取餐」／「配送中」
  - 展開後依序是：
    1. 食物：照片、名稱、「1 份・最晚 HH:MM 食用」、黃底「取餐地點：{食物點名稱}」、食物點地址（T-133）
    2. 送達地點：長者地址＋「複製地址」
    3. `Accordion`「查看位置」：MapView，只有這位長者一根定位針
    4. 過敏原紅字警示
    5. 主按鈕：「確認已取餐」或「回報拜訪」
    6. 文字連結「取消這份餐」
- 頁尾小字「只顯示派給你的進行中任務」
- 回報面板（04 中）：
  - 標題「回報：{代號}」、食物晶片
  - 三個單選：「見到本人」、「放門口，附照片」、「未見到，帶回」；純關懷時第三項顯示「未見到本人」
  - 送餐時說明「放門口需要拍照；生鮮蔬果不適用」；純關懷時提醒依實際情況回報是否見到本人
  - 照片與「重新拍照」
  - 主按鈕「送出回報」
  - 右上角「關閉」
- 完成畫面（04 右）：
  - `BrandHeader` banner「我的任務」
  - 大企鵝打勾插圖
  - 「今天的任務都完成了」＋「謝謝你，完成今天的服務回報。」
  - 青色卡「已完成 **N** 件任務」
  - 鎖頭小字「長者資料已從此頁移除」
  - 主按鈕「回到志工首頁」

### 3.4 提供者 MR-P06（03，T-136）
所有分頁的頁首都是 `BrandHeader`「提供食物」，上架分頁是「上架食物」。
- **申請**（03 左）：
  - 標語「讓多出來的一份，成為一份照顧」＋企鵝
  - 單位名稱
  - 提供者類型：5 格圖示＋文字（店家、學校、機關、個人、其他），選中時有勾
  - 單位位置：小地圖預覽、地址文字（T-133）、「在地圖上選位置」→ 底部面板的 LocationPicker
  - `InfoNote`「審核通過後，就能上架食物」
  - 主按鈕「送出申請」
  - 連結「已申請？查看審核狀態 >」
- **審核中**（沒有設計圖，比照申請頁的樣式）：企鵝、「審核中」、說明、「重新整理」。不通過時顯示原因。
- **我的庫存**（03 中）：
  - 單位名稱 ·「已通過」晶片
  - `SegmentedTabs`「我的庫存｜上架食物」
  - 三欄總計：剩餘、派出中、已送達
  - 食物列：照片、名稱、「最晚 HH:MM 食用」、「剩餘 n・派出中 n・已送達 n」、「修改」、「下架」
  - `InfoNote`「還有食物等待派送」（有可派送的食物時才出現）
  - `Accordion`「已結束的食物（N）」，預設收合
  - 主按鈕「＋ 上架新食物」
  - 頁尾小字「食物為示範資料」
- **上架食物**（03 右）：
  - `StepIndicator` 拍照 → 填寫資訊 → 上架
  - 照片：拍照或選圖，「重拍」，小字「照片選填，方便志工辨認」
  - 食物名稱
  - 類別晶片：便當、麵包、蔬果、其他。「其他」展開成乾貨、飲料、其他，對應合約 §4 的 `FoodCategory`
  - 份數 `NumberStepper`
  - 最晚食用時間（日期時間選擇）
  - 過敏原：已選的晶片可按 × 移除，「選擇過敏原」→ 底部面板的 AllergenChecklist
  - 食物點＋「變更」→ 底部面板：選既有食物點或新增
  - `InfoNote`「上架後仍可修改份數與時間」
  - 主按鈕「確認上架」

### 3.5 據點 MR-P07（04 左，T-137）
由上而下：
1. `BrandHeader` banner「據點報到」
2. 據點名稱膠囊（定位圖示）
3. 說明「請志工掃描下方 QR code 報到」
4. QR
5. 「N 秒後更新」＋進度條
6. 「今天報到・N 位」：企鵝頭像、名字、時間
7. 頁尾小字「每次更新後，請掃描最新 QR code」

QR 的更新與斷網行為不變，沿用 T-119。

### 3.6 管理系統 MR-P08（02，T-138）
- 寬度 ≥ 1024px 時是桌面版面，手機上改成一欄。
- 頁首：企鵝＋「鄰食蜂｜管理系統」；右邊是「管理員」和紅框按鈕「重置示範資料」。
- 分頁：「待審核」（黃色數字徽章）、「服務看板」、「長者名冊」。
- **服務看板**（02 上）：
  - 「今天的服務概況｜YYYY / MM / DD」
  - 5 張統計卡（圖示＋標籤＋大數字）：今日見到、待服務長者（`stats.alerts`，含送餐或關懷到期）、今日送達、今日報到、可派送食物
  - 地圖：左上標籤「位置示意・模擬資料」，右側圖例（據點、食物點、長者）
  - 右欄「食物去向」：照片、名稱、「剩餘 n｜已派送 n｜已送達 n」
- **待審核**（02 左下）：
  - 標題「待審核 N 件」
  - 表格欄位：單位名稱、類型、位置（地址，T-133）、操作（「通過」實心、「不通過」外框）
- **長者名冊**（02 右下）：
  - 右上黃色晶片「僅使用模擬資料」
  - 左邊清單：人像圖示、代號、狀態（需要送餐／需要關懷／近期已見到）、右箭頭
  - 右邊表單：
    - 代號（長者 id，唯讀）、稱呼、所屬據點（下拉）、模擬地址、過敏原、下次關懷時間
    - 「更多設定」收合區裡放下次送餐時間（Demo 劇本第 9 步要用）
    - 主按鈕「儲存變更」
  - 清單上方「新增長者」

> 設計圖 02 的下半部（待審核、長者名冊）是另外兩個分頁的內容，不是全部擠在看板上。
