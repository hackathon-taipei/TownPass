# T-108 帳號與提供者審核（後端 `meal_account`）

> 合約：`docs/system/11-meal-relay.md` v2.2（§2 角色、§3 `meal_account`／`meal_supplier`、§7 錯誤、§8 帳號端點、§11 V1、V2、V17）。
> 程式：`services/backend/src/townpass_backend/features/meal_account/`（`api.py` → `service.py`，`__init__.py` 匯出 `router`）。
> 測試：`services/backend/tests/test_meal_account.py`。

這個套件沒有自己的資料表與種子：讀寫一律用 `meal_relay` 套件根的 `repo`、`to_me()`、`to_supplier()`、`reset_demo()`（B5），路由用 `meal_router("meal_account")` 建立，錯誤丟 `MealError`，由路由自動轉成 §7 格式。

## 端點（前綴 `/meal-relay`，全部要帶 `X-Demo-User`）

| 動作 | 方法與路徑 | 角色 | 回應 | 錯誤 |
|---|---|---|---|---|
| `getMe` | `GET /me` | 全部 | `Me` | 401 `UNAUTHENTICATED` |
| `resetDemo` | `POST /demo/reset` | admin | `DemoResetResult {imported}` | 403 `FORBIDDEN_ROLE` |
| `applySupplier` | `POST /suppliers`（`SupplierApply {name, org_type, location}`） | citizen | `Supplier`（`pending`） | 409 `ALREADY_APPLIED`、422 `VALIDATION_ERROR`、403 `FORBIDDEN_ROLE` |
| `getMySupplier` | `GET /suppliers/mine` | citizen、supplier | `Supplier` 或 `null` | 403 `FORBIDDEN_ROLE` |
| `listSuppliers` | `GET /suppliers?status=pending\|approved\|rejected` | admin | `Supplier[]`（依申請時間） | 422 `VALIDATION_ERROR`（`status` 不是列舉值） |
| `reviewSupplier` | `POST /suppliers/{id}/approve`、`/reject` | admin | `Supplier` | 404 `NOT_FOUND`、409 `INVALID_STATE` |

## 規則

- **身分（V1、V2）：** 沒帶或空白的 `X-Demo-User` → 401。沒匯入的 id 由 `CurrentAccount` 視為一般市民 `citizen`，`GET /me` 回 `supplier = null`，沒有 `elder` 欄位；查詢不會把它寫進資料庫。
- **申請：** 只有 `citizen` 可以申請。這個帳號已經有申請（`pending`、`approved`、`rejected` 任何狀態）→ 409 `ALREADY_APPLIED`，被拒絕後也不能重送。申請建立 `pending` 的 `meal_supplier`，並在帳號寫入 `supplier_id`（與種子 `u-sup-3` 相同的狀態）；沒匯入的帳號會在這時寫進 `meal_account`（`role` 仍是 `citizen`、`name` 空字串），審核通過時才有帳號可以改角色。
- **我的申請：** `GET /suppliers/mine` 與 `GET /me` 的 `supplier` 用同一個 `to_me()` 找法（先看帳號的 `supplier_id`，沒有再用 `account_id` 找）。
- **審核：** 只能審 `pending`，其他狀態 → 409 `INVALID_STATE`（同一筆不能審兩次）；找不到 → 404 `NOT_FOUND`。
  - 通過 → `approved`、寫 `reviewed_at`；申請人帳號 `role = supplier`、`supplier_id = 這筆申請`（種子的 `u-sup-1`、`u-sup-2` 就是這個狀態）。
  - 不通過 → `rejected`、寫 `reviewed_at`；帳號維持 `citizen`，`GET /me` 仍看得到被拒絕的申請。
- **重置（V17）：** `POST /demo/reset` 呼叫 `reset_demo()`：清空所有 `meal_` 表並重新匯入種子，回傳匯入筆數；重置期間新增的帳號與申請都會消失。

## 合約沒寫清楚、這裡的決定

- `POST /suppliers` 成功回 200（合約沒指定狀態碼；用 FastAPI 預設，前端 `mealSend` 只看是否成功）。
- 被拒絕的申請也算「已申請」，不能重送（合約：「已有申請（任何狀態）」）；要重新申請請管理員重置 Demo。
- 沒匯入的一般市民在申請時才寫進 `meal_account`（合約 §2：提供者是「只由種子匯入」的例外），名稱留空，因為只用台北通 `id`，不存其他個資。
