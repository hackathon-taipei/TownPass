# T-116 鄰食轉運站首頁 MR-P01

台北通使用者打開鄰食轉運站的第一個畫面，對齊合約 [11-meal-relay.md](../system/11-meal-relay.md) **v2.2** §1、§2、§8、§9。
一般市民看到「長者不用操作 App、需要送餐或關懷請洽里長或最近的社區關懷據點」與據點清單（實體管道，對應題組「拿不到」），想幫忙可以「我要提供食物」；志工、提供者、據點帳號一鍵進到自己的頁面。

## 1. 畫面組成

```
MR-P01 HomePage = T01 PageContainer {
  MR-C05 StaleBanner                        斷網時顯示上次更新時間（ADR-024）
  MR-C30 HomeIntro { M01, A06 }              說明：長者不用操作 App，請洽里長或社區關懷據點
  MR-C21 PageTransition {                    getMe 回應前顯示骨架（E1，#skeleton 用 M01＋A05，大小接近進入卡片）
    MR-C33 HomeEntryCard { M01, A01 }        依角色的進入按鈕／「我要提供食物」
    | M05 EmptyState ＋ A01「重新讀取」        讀不到身分
  }
  MR-C31 HomeStationList { M03, M01, M02×n, A05, M05, A07 SourceNote }   listStations
  MR-C32 HomeVolunteerInfo { M03, M01, A01×3 }                          志工從哪裡來（§1）
}
```

| 編號 | 元件 | 用途 | props／emit |
|---|---|---|---|
| MR-C30 | `HomeIntro` | 服務說明；長者不用操作 App、找里長或社區關懷據點 | — |
| MR-C31 | `HomeStationList` | 社區關懷據點清單＋資料來源 | `stations?: Station[] \| null`（undefined 讀取中、null 讀不到）、`error?`、`source` |
| MR-C32 | `HomeVolunteerInfo` | 志工由據點經臺北市志工管理整合平臺招募、在臺北 E 大受訓；本作品不做志工申請 | `links`；`@open(url)` |
| MR-C33 | `HomeEntryCard` | 依角色的主要按鈕 | `entry: HomeEntry`、`name?`（進入自己頁面時打招呼） |

MR-C34 保留未用。

## 2. `logic/home.ts`

| 名稱 | 用途 |
|---|---|
| `useHome()` | 建立時同時呼叫 `getMe()`、`listStations()`；回傳 `me`（undefined 讀取中、null 讀不到）、`meError`、`stations`、`stationsError`、`entry`、`staleAt`、`stationSource`、`now`（每 15 秒更新）、`load()`（重新讀取）、`ready`（第一次讀取的 Promise）、`openLink`、`volunteerLinks` |
| `homeEntryOf(role)` | volunteer → `volunteer`、supplier → `supplier`、station → `station`（沿用 `shared.ts` 的 `homeRouteOf`）；citizen →「我要提供食物」→ `supplier`；admin → `null` |
| `VOLUNTEER_LINKS` | §1 的三個連結：臺北市志工管理整合平臺、臺北 E 大、志願服務管理及運用原則（按鈕用短名，全名「臺北市政府所屬各機關志願服務管理及運用原則」寫在 MR-C32 說明文字裡，避免 375px 寬的按鈕折行溢出） |
| `openLink(url)` | App 裡用 bridge `open_link`（外部瀏覽器）；一般瀏覽器開新分頁 |
| `stationSourceText(stations)`、`STATION_SOURCE_DEFAULT` | SourceNote 文字：據點 `source` 欄位去重後串起來；沒有據點時用「臺北市銀髮族服務_社區照顧關懷據點（臺北市政府社會局）」 |
| `homeErrorText(e, fallback)` | 讀取失敗時顯示 `MealApiError` 的中文訊息（§7），其他錯誤用預設文字 |

## 3. 決策

| # | 決定 | 原因 |
|---|---|---|
| 1 | 「進入」是按鈕，不自動跳轉 | 工單寫「一鍵進到自己的頁面」；自動跳轉會讓返回鍵回到首頁又被跳走，也看不到說明與據點 |
| 2 | admin 打開首頁只看到說明與據點，沒有任何按鈕 | §9：管理系統只用網址 `/#/f/meal-relay/admin`，首頁不放連結；也沒有選角色或切換身分的按鈕（§2） |
| 3 | `openLink` 暫時在 `logic/home.ts` 直接呼叫 `@/platform/bridge` 的 `send('open_link', url)` | 合約要用 bridge `open_link` 開連結，但 `@/modules/env` 還沒有 `openLink()`，`data/` 也沒有，兩者都不在本工單範圍。check-arch 不擋 logic → platform，但 [05-logic-layer.md](../system/05-logic-layer.md) 寫「平台能力包成 modules/env 的動作」；**建議整理時在 `modules/env` 加 `openLink(url)`，本檔改成從那裡匯入**（T-118 的 `qr_code_scan` 也有同樣需求） |
| 4 | 首頁沒有寫入，所以斷網時只顯示 StaleBanner | 「我要提供食物」只是換頁；申請表在提供者頁（T-117），送出鍵的停用在那裡處理 |
| 5 | getMe 與 listStations 分開處理錯誤 | 讀不到身分時仍顯示說明與據點（實體管道最重要），讀不到據點時仍能進入自己的頁面 |
| 6 | 據點清單只列名稱（副標「社區照顧關懷據點」），不放地圖 | 工單只要求列出據點名稱作為實體管道；`Station` 沒有地址或電話欄位 |

## 4. 測試

`services/web/tests/meal-relay-home.test.ts`（mock 資料層的 `getMe`、`listStations` 與 bridge；帳號 id 由真的 `currentAccountId()` 從網址 `?as=` 讀出，再對照種子帳號回傳角色）：

- 依角色進入：`u-vol-1` → volunteer、`u-sup-1` → supplier、`u-st-1` → station；`u-cit-1` 與沒匯入的帳號顯示「我要提供食物」→ supplier；`u-admin-1` 沒有按鈕

- 據點清單與 SourceNote 文字；志工三個連結，App 裡送出 `open_link`、瀏覽器開新分頁
- 讀取失敗顯示後端中文訊息、離線快取的 `stale_at` 傳給 StaleBanner、重新讀取
- 實際渲染 `HomePage.vue`（happy-dom ＋ memory router）：`u-vol-1`／`u-sup-1`／`u-st-1`／`u-cit-1` 各只有一個連結且通往自己的頁面（citizen 是「我要提供食物」→ `/f/meal-relay/supplier`）；`u-admin-1` 沒有任何連結、HTML 裡沒有 `/admin`；所有角色的按鈕只有三個志工管道，沒有「切換」「選角色」「管理系統」字樣；畫面有長者說明、據點名稱與 SourceNote；在 App 裡點志工管道送出 `open_link`
